Integration Pseudo-Code (shell.py)

In Shell.__init__ (after _break_timer setup):
self.routines_store = RoutinesStore(vault_dir)
self._routine_prompt_timer = QTimer(self)
self._routine_prompt_timer.setInterval(30_000) # 30s poll
self._routine_prompt_timer.timeout.connect(self._maybe_prompt_eating)
self._routine_prompt_timer.start()

New method:
def _maybe_prompt_eating(self):
  if not self.settings.routine_learning_enabled:
    return
  routines = self.routines_store.learned_routines()
  eating_times = routines.get("eating", {}).get("learned_times", [])
  if datetime.now().hour in eating_times:
    self.mascot.says(self.voice.say("eating_time_proactive", self._lang))
    # optional: set state to "eating"

Data Flow Summary

Step Component Data Structure
1. User picks "Eating" mascot_stage.py:_on_pick() Signal: activity_changed("Eating")
2. Activity logged shell.py:_on_activity() ActivityStore.start("Eating") → ActivityEntry(category="Eating", start=datetime.now())
3. Routine learning (NEW) routines_store.py + routines.py Extract activity_store.log(), aggregate start-times by hour, infer common times
4. Proactive prompt (NEW) shell.py:_routine_prompt_timer → _maybe_prompt_eating() Check if current hour matches learned routine, issue voice bubble
5. Feedback loop activity_store → routines_store On each user activity start, update routine model (e.g., if "Eating" at 13:00, bump hour 13's score)

Key Insights

  • START timestamps ARE stored: ActivityEntry has both .start and .end as datetime. Temporal learning is possible on day 1.
  • Aggregation already scans by window: aggregate_seconds() supports arbitrary [since, until) ranges. Can aggregate by hour/day easily.
  • No existing routine system: Must create routines.py + routines_store.py from scratch, but the pattern mirrors activity_store.py exactly.
  • Timer infrastructure exists: _board_timer (60s poll) is the template. Add _routine_prompt_timer (30–60s poll) for eating prompts.
  • Voice lines are deterministic + LLM-optional: Add eating_time_prompt variants to voice_lines.json; can be personalized via LLM later.
  • No user profile today: Must add routine_learning_enabled toggle to settings, and routines.json to vault.
  • Eating state is trivial: 3 lines in mascot_stage.py + 1 line in poses.py + a few voice_lines.json entries.
